# KevBox Admin — Plan 4: Deploy to persovps Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Run the `apps/web` Fastify process as a systemd service on persovps behind nginx, serving `https://admin.kevbox.dev` over TLS, with a one-command `deploy.sh` that builds (core + SPA + server bundle), `scp`s the artifacts to the VPS, and restarts the unit.

**Architecture:** `deploy.sh` runs on the operator's laptop: it builds `@kevbox-admin/core` and `apps/web` (Vite SPA + bundled Node server), tars the runtime artifacts, `scp`s the tarball to persovps over SSH (mirroring the NuvioTV `release.sh` scp-to-persovps pattern: alias `persovps`, port `1788`, `sudo install`/`sudo tee` over ssh), unpacks it into `/opt/kevbox-admin`, and `sudo systemctl restart kevbox-admin`. The Fastify process listens on `127.0.0.1:$PORT` (loopback only); nginx terminates TLS for `admin.kevbox.dev` and reverse-proxies to that port. Secrets live ONLY in `/etc/kevbox-admin/env` on the VPS (read by the systemd unit via `EnvironmentFile=`), never in git.

**Tech Stack:** bash, ssh/scp, systemd, nginx, certbot (Let's Encrypt), Node 20+ on the VPS, the existing persovps SSH config (alias `persovps`, port `1788`).

**Spec:** /home/kevin/projects/NuvioTV/kevbox-admin/docs/superpowers/specs/2026-06-09-kevbox-admin-design.md

## Prerequisites & assumptions (read before starting)

This plan assumes:
- **Plan 1** (scaffold + `@kevbox-admin/core`) is merged. `npm run build -w @kevbox-admin/core` produces `packages/core/dist`.
- **The web plan** is merged, so `apps/web` exists with:
  - `npm run build -w @kevbox-admin/web` producing **two outputs**: the Vite SPA in `apps/web/dist/public/` and a **single, fully self-contained esbuild bundle** of the Node server at `apps/web/dist/server.js`. Every runtime dependency (`fastify`, `@fastify/static`, `pg`, `@supabase/supabase-js`) **and** the workspace package `@kevbox-admin/core` are **inlined** into that one file (web plan Task 1 `build:server` = `esbuild … --bundle`).
  - The Fastify server reads `PORT`, `SUPABASE_DB_URL`, `SUPABASE_URL`, `SUPABASE_ANON_KEY`, and `ADMIN_EMAILS` from `process.env`, binds to `host: "127.0.0.1"`, serves the SPA from `dist/public` (resolved relative to the bundle), and exposes an unauthenticated `GET /healthz` that runs `select 1` against the pool.

  > Because `dist/server.js` is a self-contained bundle, the deploy artifact is **just `dist/`** (`server.js` + `public/`) — there is **no `node_modules` to ship and no `npm ci` on the VPS**, and the unresolvable `@kevbox-admin/core` workspace `*` dependency never reaches the VPS. (`pg`/`fastify`/`@supabase/supabase-js` are pure-JS with no native addons, so they bundle cleanly. If a future dependency adds a native addon, mark just that one `--external` in the web build and ship its `node_modules` subtree.)
- The operator has **SSH access to persovps** (alias `persovps`, port `1788`, per `~/.ssh/config`) and **passwordless `sudo`** on the VPS (the NuvioTV `release.sh` already relies on `sudo` over ssh there).
- persovps already runs **nginx** (it serves `tv.kevbox.dev`) and has **certbot** installed.
- Node 20+ is installed on persovps. (Verify in Task 3, Step 1; if missing, install via NodeSource.)

The host is parameterized at the top of `deploy.sh` (`SSH_ALIAS`, `SSH_PORT`, `REMOTE_DIR`, `PORT`), matching the `release.sh` convention of env-overridable variables.

## Task 2: `deploy.sh` (build + scp + restart)

**Files:**
- Create: `deploy.sh`

- [ ] **Step 1: Create `deploy.sh`**

```bash
#!/usr/bin/env bash
# KevBox Admin deploy pipeline (admin.kevbox.dev on persovps).
# Mirrors the NuvioTV release.sh scp-to-persovps pattern (alias persovps, port 1788,
# sudo install / sudo systemctl over ssh).
#
# Usage: ./deploy.sh
#
# What it does:
#   1. Builds @kevbox-admin/core and apps/web (Vite SPA + a self-contained esbuild
#      server bundle at apps/web/dist/server.js — all deps incl. @kevbox-admin/core inlined).
#   2. Stages the runtime artifact: just dist/ (server.js + public/). No node_modules,
#      no package.json, no npm ci — the bundle is self-contained.
#   3. tars the stage and scp's it to persovps:/tmp.
#   4. Over ssh: unpacks into $REMOTE_DIR (atomic swap via a `current` symlink) and
#      restarts the systemd unit.
#   5. Smoke-checks the live site (curl https://admin.kevbox.dev/healthz then /).
#
# Secrets are NOT shipped by this script — they live only in /etc/kevbox-admin/env
# on the VPS (see deploy/env.example and deploy/README.md). One-time VPS bootstrap
# (systemd unit, nginx, certbot, env file) is in deploy/README.md.
set -euo pipefail

note() { printf '\033[36m→ %s\033[0m\n' "$*"; }
err()  { printf '\033[31m✗ %s\033[0m\n' "$*" >&2; exit 1; }

# --- persovps connection + deploy target (override via env; mirrors release.sh) ---
SSH_ALIAS="${KEVBOX_SSH_ALIAS:-persovps}"
SSH_PORT="${KEVBOX_SSH_PORT:-1788}"
REMOTE_DIR="${KEVBOX_ADMIN_REMOTE_DIR:-/opt/kevbox-admin}"
SERVICE="${KEVBOX_ADMIN_SERVICE:-kevbox-admin}"
DOMAIN="${KEVBOX_ADMIN_DOMAIN:-admin.kevbox.dev}"

REPO="$(git -C "$(dirname "$0")" rev-parse --show-toplevel)"
cd "$REPO"

# --- 1. Build core + web --------------------------------------------------------
note "Building @kevbox-admin/core…"
npm run build -w @kevbox-admin/core --silent

note "Building apps/web (SPA + server bundle)…"
npm run build -w @kevbox-admin/web --silent

SERVER_ENTRY="apps/web/dist/server.js"
SPA_DIR="apps/web/dist/public"
[[ -f "$SERVER_ENTRY" ]] || err "Missing $SERVER_ENTRY — did the web build run? (npm run build -w @kevbox-admin/web)"
[[ -d "$SPA_DIR" ]]      || err "Missing $SPA_DIR — Vite SPA build output not found"
note "Build OK: $SERVER_ENTRY + $SPA_DIR/"

# --- 2. Stage the self-contained runtime artifact (just dist/) -------------------
STAGE="$(mktemp -d)"
trap 'rm -rf "$STAGE"' EXIT
note "Staging runtime artifact in $STAGE…"
mkdir -p "$STAGE/dist"
cp -R apps/web/dist/. "$STAGE/dist/"
# dist/server.js is a self-contained esbuild bundle (all deps + @kevbox-admin/core
# inlined), so there is NO package.json/lockfile to ship and NO npm ci to run on the VPS.

# --- 3. tar + scp to persovps ---------------------------------------------------
TARBALL="kevbox-admin-$(date +%Y%m%d-%H%M%S).tgz"
note "Packing $TARBALL…"
tar -C "$STAGE" -czf "/tmp/$TARBALL" .
note "Uploading $TARBALL to $SSH_ALIAS:/tmp…"
scp -P "$SSH_PORT" "/tmp/$TARBALL" "$SSH_ALIAS:/tmp/$TARBALL"
rm -f "/tmp/$TARBALL"

# --- 4. Unpack into a timestamped release dir + atomic symlink swap + restart ----
RELEASE="release-$(date +%Y%m%d-%H%M%S)"
note "Deploying $RELEASE on $SSH_ALIAS and restarting $SERVICE…"
ssh "$SSH_ALIAS" -p "$SSH_PORT" "set -euo pipefail
  sudo mkdir -p '$REMOTE_DIR/releases/$RELEASE'
  sudo tar -C '$REMOTE_DIR/releases/$RELEASE' -xzf '/tmp/$TARBALL'
  rm -f '/tmp/$TARBALL'
  sudo ln -sfn '$REMOTE_DIR/releases/$RELEASE' '$REMOTE_DIR/current'
  sudo systemctl restart '$SERVICE'
  # Prune all but the 5 most recent releases.
  ls -1dt '$REMOTE_DIR'/releases/release-* | tail -n +6 | xargs -r sudo rm -rf"

# --- 5. Smoke check -------------------------------------------------------------
note "Waiting for service to come up…"
ssh "$SSH_ALIAS" -p "$SSH_PORT" "sudo systemctl is-active '$SERVICE'" \
  || err "Service '$SERVICE' is not active after restart — check: ssh $SSH_ALIAS -p $SSH_PORT 'sudo journalctl -u $SERVICE -n 50'"
# /healthz runs `select 1` against the pool, so a 200 here proves nginx + the unit +
# DB connectivity (catches a wrong/unreachable SUPABASE_DB_URL that a static-/ check misses).
note "Smoke-checking https://$DOMAIN/healthz …"
HEALTH_CODE="$(curl -s -o /dev/null -w '%{http_code}' "https://$DOMAIN/healthz" || echo 000)"
[[ "$HEALTH_CODE" == "200" ]] \
  || err "https://$DOMAIN/healthz returned $HEALTH_CODE — service or DB connectivity is broken (deploy/README.md troubleshooting; check SUPABASE_DB_URL host/role)"
note "Smoke-checking https://$DOMAIN …"
HTTP_CODE="$(curl -s -o /dev/null -w '%{http_code}' "https://$DOMAIN/" || echo 000)"
case "$HTTP_CODE" in
  200|301|302) note "Live: https://$DOMAIN returned $HTTP_CODE (healthz OK)" ;;
  *) err "https://$DOMAIN returned $HTTP_CODE — check nginx + the unit (deploy/README.md troubleshooting)" ;;
esac

note "Deploy complete: $RELEASE → https://$DOMAIN"
```

## Task 4: nginx reverse proxy for `admin.kevbox.dev`

**Files:**
- Create: `deploy/nginx-admin.kevbox.dev.conf`

- [ ] **Step 1: Create `deploy/nginx-admin.kevbox.dev.conf`** (HTTP-only block; certbot adds the TLS/443 block in Task 5)

```nginx
# admin.kevbox.dev — reverse proxy to the KevBox Admin Fastify service on 127.0.0.1:8787.
# Pre-TLS: this is the HTTP (port 80) server block. After certbot --nginx (Task 5) runs,
# certbot rewrites this file to add the 443/TLS server and a 80→443 redirect.
# Websockets are NOT needed (the SPA polls /api/* over plain HTTPS).
#
# PORT here MUST match PORT in /etc/kevbox-admin/env (default 8787).

# Brute-force / abuse backstop for an internet-exposed admin (the SPA also hits Supabase
# auth directly, but every /api/* call triggers a server-side getUser). 10 r/s avg, burst 20.
# limit_req_zone lives in the http context; a file in sites-enabled/conf.d is included there.
limit_req_zone $binary_remote_addr zone=kevbox_admin:10m rate=10r/s;

server {
    listen 80;
    listen [::]:80;
    server_name admin.kevbox.dev;

    # Modest upload cap; admin requests are tiny JSON.
    client_max_body_size 1m;

    # Security headers (single-origin admin SPA, no third-party embeds).
    add_header X-Content-Type-Options nosniff always;
    add_header X-Frame-Options DENY always;
    add_header Referrer-Policy no-referrer always;
    # connect-src must allow the Supabase project (the SPA signs in with the anon key).
    # Replace CHANGE_ME.supabase.co with the real project host.
    add_header Content-Security-Policy "default-src 'self'; connect-src 'self' https://CHANGE_ME.supabase.co; img-src 'self' data:; style-src 'self' 'unsafe-inline'; script-src 'self'; frame-ancestors 'none'; base-uri 'self'" always;
    # HSTS: certbot's managed TLS block is the right place; if it doesn't add one, uncomment
    # after Task 5 (only ever on HTTPS): add_header Strict-Transport-Security "max-age=31536000" always;

    location / {
        limit_req zone=kevbox_admin burst=20 nodelay;
        proxy_pass http://127.0.0.1:8787;
        proxy_http_version 1.1;
        proxy_set_header Host              $host;
        proxy_set_header X-Real-IP         $remote_addr;
        proxy_set_header X-Forwarded-For   $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_read_timeout 30s;
    }
}
```

## Rotating secrets

Secrets live only in `/etc/kevbox-admin/env` (and, for the anon key, baked into the SPA).

- **DB password / `SUPABASE_DB_URL` or `ADMIN_EMAILS`** — edit the env file and restart; no rebuild:
  ```bash
  ssh -t persovps -p 1788 "sudo -e /etc/kevbox-admin/env && sudo systemctl restart kevbox-admin"
  ```
  (To rotate the DB password itself, `alter role kevbox_admin with password '…'` in the Supabase
  SQL editor first, then update the env string.)
- **`SUPABASE_ANON_KEY`** — this one is ALSO baked into the SPA at build time
  (`VITE_SUPABASE_ANON_KEY`). Rotating it requires editing **both** the server env file **and**
  `apps/web/.env`, then **re-running `./deploy.sh`** (a plain restart is not enough — the old key
  stays in the shipped JS until you rebuild).
- **Removing an admin** — drop the address from `ADMIN_EMAILS` and restart (takes effect on the
  next request; existing JWTs are still rejected because the allowlist is checked per-request).

## Rollback

`deploy.sh` keeps the 5 most recent releases in `/opt/kevbox-admin/releases/`. To roll
back to the previous release, repoint `current` and restart:

```bash
ssh persovps -p 1788 "set -e
  PREV=\$(ls -1dt /opt/kevbox-admin/releases/release-* | sed -n '2p')
  echo \"Rolling back to \$PREV\"
  sudo ln -sfn \"\$PREV\" /opt/kevbox-admin/current
  sudo systemctl restart kevbox-admin"
curl -I https://admin.kevbox.dev/
```

To roll back further, list releases (`ls -1dt /opt/kevbox-admin/releases/release-*`)
and point `current` at the desired one. Secrets/env are unaffected by rollback (they
live in `/etc/kevbox-admin/env`, outside the release dirs).

## Troubleshooting

- **502 from nginx** → the unit is down. `ssh persovps -p 1788 "sudo systemctl status kevbox-admin --no-pager; sudo journalctl -u kevbox-admin -n 50 --no-pager"`. Common cause: a bad value in `/etc/kevbox-admin/env` (e.g. `SUPABASE_DB_URL`).
- **Service active but `/healthz` or `/api/*` returns 500/503** → DB connectivity. Most common cause on a fresh VPS: `SUPABASE_DB_URL` points at the **direct** host `db.<ref>.supabase.co`, which is **IPv6-only** — an IPv4-only VPS gets `ENETUNREACH`/`ENOTFOUND`. Fix: use the **Session pooler** host (`…pooler.supabase.com:5432`, IPv4-reachable; copy it from Project Settings → Database → Connection string → Session pooler). Also confirm `?sslmode=require`, the `kevbox_admin` role/password, and that the role has the grants from "Least-privileged DB role". Quick check from the VPS: `ssh persovps -p 1788 "getent hosts <db-host>; node -e 'require(\"net\").connect(5432,\"<db-host>\").on(\"connect\",()=>{console.log(\"ok\");process.exit()}).on(\"error\",e=>{console.log(e.code);process.exit()})'"`.
- **`/api/*` returns 401 with a valid token** → `ADMIN_EMAILS` mismatch, or `SUPABASE_URL`/`SUPABASE_ANON_KEY` wrong (JWT verification fails). Confirm they match the Supabase project.
- **Not listening on 127.0.0.1:8787** → `PORT` in the env file disagrees with nginx `proxy_pass`, or the server binds `0.0.0.0`. `ss -ltnp | grep 8787`.
- **Cert won't issue** → DNS not pointing at the VPS yet (`dig +short admin.kevbox.dev A`); wait for TTL and retry certbot.
